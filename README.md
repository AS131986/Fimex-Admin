# Fimex Admin — QA документация

## Назначение проекта

Эта папка — постоянная база QA-знаний по проекту **Fimex Admin** (веб-админка). Здесь хранится вся документация, которую Senior QA Engineer (AI QA Partner) ведёт в паре с QA Lead: описания страниц, чек-листы, результаты тестовых прогонов, реестр дефектов, подтверждённые решения и открытые вопросы.

## Архитектура документации

Корень проекта:

- `README.md` — этот файл: назначение, структура, правила.
- `documentation-standard.md` — утверждённые форматы `spec.md` и `checklist.md`, правила ID, приоритетов и оформления.
- `project-map.md` — карта страниц админки и статус их изучения/тестирования.
- `decisions.md` — подтверждённые решения QA Lead по продукту и процессу.
- `open-questions.md` — открытые вопросы, ожидающие решения QA Lead.
- `.gitignore` — исключения для временных, служебных и чувствительных файлов.

Дополнительные каталоги создаются только по мере необходимости:

- `requirements/` — общие бизнес-правила, применимые к нескольким страницам.
- `pages/<page-id>/spec.md` и `pages/<page-id>/checklist.md` — документация конкретной страницы.
- `test-runs/` — результаты тестовых прогонов (PASS/FAIL/BLOCKED/NOT RUN) по страницам и датам.
- `defects/` — реестр дефектов.
- `evidence/` — доказательства (скриншоты, логи, видео, трассировки).

Пустые каталоги заранее не создаются.

## Правила именования

- Имена файлов и папок — латиницей, в нижнем регистре, через дефис (kebab-case), например `pages/users-list/spec.md`.
- Не использовать суффиксы `final`, `new`, `updated`, `v2` и подобные — документ всегда один и обновляется на месте.
- Тестовые сущности в самой админке (не файлы документации) — с префиксом `QA_TEST_`.

## Правила создания и обновления файлов

- Один источник истины на каждое правило/страницу: один актуальный `spec.md`, один актуальный `checklist.md`.
- Перед изменением существующего документа — перечитать его актуальную версию, чтобы не потерять чужие правки; при конфликте — не перезаписывать, зафиксировать конфликт и запросить решение QA Lead.
- Новые каталоги и файлы создаются только при реальной необходимости, не заранее.
- Промежуточные рассуждения агента не сохраняются в документации.
- Результаты тестовых прогонов хранятся отдельно от `checklist.md` (в `test-runs/`); сам чек-лист остаётся шаблоном с пустыми чекбоксами.
- Дефекты фиксируются в `defects/` по формату из `documentation-standard.md` / раздела о дефектах проектных инструкций.
