# NOM-F-002 — Редактирование кода товара в списке позволяет сохранить произвольные символы (не только буквы/цифры)

- **Страница:** Settings → Nomenclature → модель «iPhone 13» → список товаров (инлайн-редактирование ячейки «Code»).
- **Окружение:** стейдж `https://oman.itway.bz/` (роль супер админ).
- **Браузер/платформа:** Chrome (Claude in Chrome).
- **Предусловия:** открыт список товаров модели «iPhone 13»; выбран реальный товар `MLPH3 B/A — British iPhone 13 128Gb Pink`.
- **Шаги воспроизведения:**
  1. Кликнуть по значению кода товара в столбце «Code» (инлайн-редактирование).
  2. Ввести `<script>alert(1)</script>`.
  3. Нажать Enter.
- **Ожидаемый результат:** согласно BR-NOM-051 («Код обязателен (буквы и цифры)...») сохранение значения с символами, не являющимися буквами/цифрами, должно быть отклонено с ошибкой валидации формата.
- **Фактический результат:** значение сохраняется без ошибки; в столбце «Code» отображается `<script>alert(1)</script>` как обычный текст. Важное уточнение по безопасности: строка отрендерена как текст (escaped), JavaScript не выполнился — признаков XSS-уязвимости в списке товаров не обнаружено. Проблема именно в отсутствии валидации формата поля, а не в безопасности рендеринга.
- **Severity:** Medium (риск засорения данных произвольными символами; специально искал признаки XSS — не подтвердились).
- **Priority:** P2.
- **Частота воспроизведения:** воспроизведено стабильно, 1/1 попытка.
- **Доказательства:** скриншот в ходе сессии тестирования 2026-11-14 (история диалога с QA Lead); не сохранён отдельно в `evidence/`. Значение восстановлено до исходного `MLPH3 B/A` сразу после проверки.
- **Связанные Console/Network данные:** не проверялись отдельно.
- **Ссылка на требование:** BR-NOM-051. Та же оговорка, что и в NOM-F-001: BR сформулирована для раздела «Добавление товара», явного BR для редактирования существующего кода нет. Открыт вопрос Q-006.
- **Статус подтверждения:** подтверждённый факт поведения; классификация как дефекта зависит от ответа на Q-006.
- **Примечание (связанные наблюдения, подтверждающие корректную работу части валидации):**
  - Попытка сохранить точный дубликат кода+RC существующего товара (`MLPF3 B/A`, уже занят товаром в строке 2) была корректно отклонена сервером с ошибкой «The code has already been taken» — соответствует BR-NOM-044. Это **не дефект**, а подтверждение правильной работы проверки уникальности.
  - Попытка сохранить пустой код при инлайн-редактировании отклонена с ошибкой «The code cannot be empty» — при редактировании существующего товара это ожидаемо (в отличие от создания нового товара, где пустой код по BR-NOM-051 означает автогенерацию). Поведение признано корректным, а не противоречием.
