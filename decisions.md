# Decisions Log — Fimex Admin

Реестр подтверждённых решений QA Lead по продукту, бизнес-логике и процессу тестирования. Решение считается действующим, пока не изменено новым подтверждённым решением той же функциональности.

## Формат записи

```markdown
## D-<NNN> — <Короткое название решения>
- **Дата:**
- **Автор решения:** QA Lead
- **Контекст/вопрос:**
- **Решение:**
- **Затронутая функциональность/страница:**
- **Связанные документы:** (spec.md, open-questions.md и т.п.)
```

Правила:

- Решения нумеруются последовательно (`D-001`, `D-002`, ...), номера не переиспользуются.
- Новое решение, противоречащее более раннему по той же функциональности, не заменяет старую запись, а добавляется новой записью со ссылкой на предыдущую; приоритет имеет более позднее подтверждённое решение.
- Вымышленные или неподтверждённые решения в этот файл не добавляются.

## D-001 — Статус окружения `https://oman.itway.bz/`
- **Дата:** 2026-11-14
- **Автор решения:** QA Lead

- **Решение:** `https://oman.itway.bz/` — это **стейдж** (staging), не production. Существует отдельный прод. Стейдж представляет собой полностью переписанный вариант прода с оптимизацией кода (старый прод был перегружен костылями). Решение закрывает Q-001.
- **Затронутая функциональность/страница:** все разделы админки — определяет допустимость изменяющих операций и тестовых данных на этом окружении (раздел 7 инструкций).
- **Связанные документы:** `open-questions.md` (Q-001 помечен «отвечен»), `project-map.md`.

## D-002 — Отображение страны «Япония» в разделе Suppliers при EN-интерфейсе
- **Дата:** 2026-11-14
- **Автор решения:** QA Lead
- **Контекст/вопрос:** При первичном осмотре раздела Suppliers элемент «Япония» отображался не переведённым (по-русски, без флага), в отличие от UAE/USA — было зафиксировано как неподтверждённое наблюдение в `project-map.md`.

- **Связанные документы:** `project-map.md` (наблюдение снято).

## D-003 — Скоуп и условия тестирования этапов 1–2 страницы «Номенклатура»
- **Дата:** 2026-11-14
- **Автор решения:** QA Lead
- **Контекст/вопрос:** 5 уточняющих вопросов перед началом изменяющих операций на этапах «Дерево и список» и «Бренды, категории и модели — создание/редактирование/удаление».
- **Решение:**
  1. Этап 2 покрывает только общие правила бренда/категории/подкатегории (название, уникальность, trim, soft delete, каскад, drag&drop, контекстное меню — включая правый клик для Rename/Edit, подтверждения удаления). Содержимое вкладок «Главные» (иконки/характеристики), «Вывод данных», «Группы товаров» тестируется отдельно на этапе 3.
  2. Стейдж `oman.itway.bz` — общий, параллельно могут работать другие (разработчики/QA). Тестовые сущности изолируются префиксом `QA_TEST_`; результаты проверок интерпретируются с поправкой на возможные конкурентные изменения со стороны.
  3. Роли: пока тестируем только под супер админом. Проверка прав по ролям (admin / менеджер / менеджер отдела продаж / менеджер склада / менеджер сервиса) — отдельная задача, выполняется позже.
  4. BR-NOM-013 («нельзя удалить бренд/категорию, если есть товар в продаже») — проверка отложена до этапа 4 (создание товаров), так как требует тестового товара. В `checklist.md` отмечена как зависимая/отложенная (NOM-DEP001), а не как пройденная.
  5. Страна поставщика (Settings → Purchasing and sales) не нужна для этапов 1–2 — тестируем только бренд/категорию/подкатегорию внутри товарного дерева Номенклатуры.
- **Затронутая функциональность/страница:** Nomenclature, этапы 1–2.
- **Связанные документы:** `pages/nomenclature/spec.md`, `pages/nomenclature/checklist.md`.


## D-004 — Терминология иерархии Номенклатуры: «Модель», без отдельного уровня «Группа»
- **Дата:** 2026-11-14
- **Автор решения:** QA Lead
- **Контекст/вопрос:** Q-005 — третий уровень дерева в UI называется «Model» («+ New Model»), тогда как в ТЗ и в исходной документации использовался термин «подкатегория»; дополнительно в ТЗ фигурировал термин «группа» (между подкатегорией и товарами, BR-NOM-004, BR-NOM-037–039, BR-NOM-077, BR-NOM-078, BR-NOM-082), природа которого была не до конца ясна.
- **Решение:** Иерархия Номенклатуры — **Бренд → Категория → Модель → Товары** (ровно 4 уровня, без отдельного узла «Группа»). Термин «группа» из ТЗ — синоним «модели», отдельного узла дерева не образует. Документация (`spec.md`, `checklist.md`) приведена к этой терминологии: все упоминания «подкатегория»/«группа» (в значении уровня дерева) заменены на «модель». Термин «Группы товаров» (название вкладки настроек модели/категории) и «группа» в контексте комбинаций характеристик (BR-NOM-055, BR-NOM-064, BR-NOM-070) — отдельные понятия, не затронуты этим решением. Закрывает Q-005.
- **Затронутая функциональность/страница:** Nomenclature — вся документация по дереву, бренду, категории, модели, архиву.
- **Связанные документы:** `pages/nomenclature/spec.md`, `pages/nomenclature/checklist.md`, `open-questions.md` (Q-005 помечен «отвечен»).

## D-005 — Прочие уточнения по этапу 2 (Номенклатура)
- **Дата:** 2026-11-14
- **Автор решения:** QA Lead
- **Контекст/вопрос:** Три пункта из промежуточного отчёта по этапу 2: (а) назначение тумблера Archive и вкладок Active/Archived section; (б) достаточность проверки BR-NOM-015 (лимит 100 символов) через нативный `maxlength`, без прямого вызова API; (в) проверка NOM-N205 (загрузка не-SVG логотипа), заблокированная в текущей сессии из-за отсутствия разрешения на загрузку файлов.
- **Решение:**
  1. Подтверждено: в архиве (при включённом тумблере Archive) действительно хранятся все удалённые данные — это ожидаемое поведение, более глубокая проверка механики вкладок Active/Archived section в рамках этапов 1–2 не требуется (отложено до этапа 6 «Архив и восстановление»).
  2. Проверка BR-NOM-015 признана достаточной в текущем виде (PASS по существу правила через подтверждённое ограничение `maxlength=100` на уровне поля ввода) — дополнительный прямой вызов API не требуется.
  3. NOM-N205 (загрузка не-SVG файла как логотип) QA Lead уже проверял вручную самостоятельно — повторная автоматизированная проверка в рамках этой сессии не требуется, тест остаётся закрытым без отдельного прогона со стороны ассистента.
  4. Тестовый бренд `QQQQ...Q` (100 символов, без префикса `QA_TEST_`) оставлен как есть по решению QA Lead; отклонение от правила 7.2 зафиксировано как сознательно принятое, дальнейших действий не требуется.
- **Затронутая функциональность/страница:** Nomenclature, этап 2 (Бренд/Категория/Модель), частично этап 6 (Архив).
- **Связанные документы:** `test-runs/nomenclature-stage1-2-run1.md`.
