# Номенклатура

## 1. Общая информация

- **Название:** Номенклатура
- **ID страницы:** nomenclature
- **Раздел:** Settings → Nomenclature (в основном меню — верхнеуровневый пункт в разделе Settings)
- **URL/маршрут:** не зафиксирован (требуется уточнение при первом открытии страницы)
- **Назначение:** Управление товарной иерархией (бренд → категория → подкатегория → группа) и товарами внутри неё: создание/редактирование/удаление брендов, категорий, подкатегорий и товаров; настройка того, как формируется название и внешний вид товара; архивирование и восстановление.
- **Доступные роли:** права «Просмотр», «редактирование», «удаление» настраиваются на странице Settings → Users (BR-NOM-018). Конкретное распределение по ролям (admin / менеджер / менеджер отдела продаж / менеджер склада / менеджер сервиса / супер админ) не подтверждено — требует проверки на странице Users.
- **Источники требований:** ТЗ — ClickUp task «Номенклатура» (#z8wf5rj831, `https://app.clickup.com/t/90182877012/z8wf5rj831`), подтверждено QA Lead 2026-11-14.
- **Ссылка на Figma:** не предоставлена.
- **Статус изучения:** ТЗ изучено полностью; UI пока не осмотрен (предстоит на этапе 1 «Дерево и список»).

## 2. Элементы интерфейса

- **Дерево номенклатуры** (левая часть страницы): уровни бренд → категория → подкатегория → группа; раскрытие/сворачивание стрелкой; кнопки добавления под каждым уровнем; drag&drop для изменения порядка; правый клик — контекстное меню.
- **Таблица товаров** (правая часть, при выборе группы в дереве): фото, код, RC, название, вес, действия (редактирование, настройка сканирования, дублирование, удаление). Над таблицей — название выбранного элемента, карандаш (редактирование подкатегории), «+» (добавление товара).
- **Вкладка «Архив»** — рядом с «Номенклатурой», отдельный режим с деревом и товарами для восстановления.
- **Окно «Добавить бренд»** — название, логотип light, логотип dark.
- **Окно «Добавить категорию / подкатегорию»** — вкладки «Главные» (по умолчанию открыта), «Вывод данных», «Группы товаров».
- **Окно «Добавить товар» / окно редактирования товара** — фото, код, вес, поля характеристик.
- **Окно «Настройка сканирования»** — режим (Без IMEI / Один / Два), код производства, количество символов.
- Массовое назначение RC — «+ RC» над таблицей товаров.

## 3. Бизнес-правила

Источник всех правил ниже, если не указано иное: ТЗ ClickUp #z8wf5rj831. Статус подтверждения: **подтверждено** (зафиксировано в ТЗ), кроме отдельно помеченных.

### Дерево номенклатуры

- **BR-NOM-001** — Раскрытие/сворачивание уровня. Условие: клик по стрелке (▶ свёрнут, ▼ развёрнут). Поведение: дочерние элементы показываются с отступом.
- **BR-NOM-002** — Кнопки добавления. Условие: под каждым уровнем. Поведение: «+ New Brand» (корень), «+ New Category» (под брендом), «+ New Model» (под категорией); если элементов нет — показывается только кнопка.
- **BR-NOM-003** — Изменение порядка. Условие: drag&drop внутри родителя. Поведение: новый порядок сохраняется автоматически после отпускания.
- **BR-NOM-004** — Название группы в дереве. Условие: группа отображается в дереве. Поведение: название берётся из блока «Дерево» вкладки «Вывод данных» родительской подкатегории. Пример из ТЗ: характеристики Country, Apple, Model, Name of countries → «China iPhone 18 Pro Max A3718 China».

### Общие правила для бренда, категории и подкатегории

- **BR-NOM-005** — Название обязательно, максимум 100 символов; пробелы в начале/конце удаляются автоматически (trim).
- **BR-NOM-006** — Уникальность названия без учёта регистра: бренд — среди всех брендов; категория — внутри своего бренда; подкатегория — внутри своей категории.
- **BR-NOM-007** — Иконки light и dark необязательны; принимается только SVG; ограничения размера файла нет.
- **BR-NOM-008** — Правый клик по элементу дерева открывает контекстное меню.
- **BR-NOM-009** — Rename: название редактируется прямо в дереве инлайн; сохранение по Enter или клику вне поля.
- **BR-NOM-010** — Edit: открывается окно с текущими данными элемента.
- **BR-NOM-011** — Delete: требует подтверждения «Удалить <бренд / категорию / подкатегорию> «Название»?» с кнопками «Отмена» и «Удалить».
- **BR-NOM-012** — Удаление мягкое (soft delete). Каскадно удаляются вложенные уровни и всё привязанное к ним: настройки на страницах «Проценты», «Карго» (включая вес), «Гарантии», привилегии поставщика. Список привязанных настроек открытый — в ТЗ помечено «будет пополняться».
- **BR-NOM-013** — Нельзя удалить бренд/категорию/подкатегорию, если внутри есть товар в продаже.

### Ошибки (общие для бренда/категории/подкатегории)

- **BR-NOM-014** — Пустое название → «Заполните название <бренда / категории / подкатегории>.»
- **BR-NOM-015** — Больше 100 символов → «Максимальная длина — 100 символов.»
- **BR-NOM-016** — Название уже существует → «<Бренд / Категория / Подкатегория> с таким названием уже существует.»
- **BR-NOM-017** — Загружен не-SVG файл иконки → «Недопустимый формат файла.»

### Права

- **BR-NOM-018** — Права «Просмотр», «редактирование», «удаление» настраиваются на странице Settings → Users. Детальное распределение по ролям — вне скоупа этого документа, проверяется отдельно.

### Сценарий: Бренд

- **BR-NOM-019** — Добавление: «+ New Brand» → окно «Добавить бренд» (название, логотип light, логотип dark). После сохранения бренд появляется в дереве.
- **BR-NOM-020** — Управление: контекстное меню — Rename, Edit, Delete (Duplicate для бренда не предусмотрен).

### Сценарий: Категория и подкатегория — добавление

- **BR-NOM-021** — «+ New Category» / «+ New Model» → окно «Добавить категорию / подкатегорию» с вкладками «Главные», «Вывод данных», «Группы товаров»; по умолчанию открыта «Главные». После сохранения элемент появляется в дереве.

### Вкладка «Главные» (категория/подкатегория)

- **BR-NOM-022** — Содержит: название, иконки, набор характеристик.
- **BR-NOM-023** — Характеристики выбираются из «Справочника» через «+»; одну и ту же характеристику нельзя добавить дважды.
- **BR-NOM-024** — Характеристики выводятся по алфавиту.
- **BR-NOM-025** — Нельзя убрать характеристику, пока она используется во вкладке «Вывод данных» — сначала убрать её там.
- **BR-NOM-026 (наследование)** — Пока у категории/подкатегории нет своих характеристик — используются характеристики родителя. Как только добавлена хотя бы одна своя — используются только свои (родительские больше не наследуются).

### Вкладка «Вывод данных» (категория/подкатегория)

- **BR-NOM-027** — Задаёт, из каких характеристик и в каком порядке формируется название товара. Блоки: «По умолчанию», «Дерево», «Таргет» и другие — каждый настраивается отдельно.
- **BR-NOM-028** — Характеристики добавляются через «+» из тех, что выбраны на вкладке «Главные»; требуется минимум одна.
- **BR-NOM-029** — Порядок характеристик меняется перетаскиванием; удаление — крестиком.
- **BR-NOM-030** — Если по категории есть товар в продаже, любое изменение блока (добавление/удаление/смена порядка) показывает предупреждение: «Есть товар в продаже. Изменение поменяет названия товаров. Продолжить?»
- **BR-NOM-031** — Под списком показывается пример итогового названия: первые значения каждой характеристики из «Справочника» в текущем порядке (пример из ТЗ: «iPhone 16 Pro Max 128Gb Black»).
- **BR-NOM-032** — «Info» показывает список страниц, где выводится это название.
- **BR-NOM-033** — Изменения в «Вывод данных» применяются и к уже существующим товарам категории (переименование задним числом).
- **BR-NOM-034 (наследование)** — Пока на вкладке «Главные» нет своих характеристик, вкладка «Вывод данных» неактивна, используется «Вывод данных» родителя.

### Управление категорией/подкатегорией

- **BR-NOM-035** — Контекстное меню: Rename, Edit, Duplicate, Delete.
- **BR-NOM-036** — Duplicate: копия появляется сразу под оригиналом с названием «<Название> copy», сразу в режиме Rename. Копируется всё: характеристики, иконки, вывод данных, вложенные подкатегории, настройки процентов/карго/гарантий, привилегии поставщика.

### Товары — список

- **BR-NOM-037** — При выборе группы в дереве справа выводится таблица её товаров: фото, код, RC, название, вес, действия. Над таблицей — название выбранного элемента, карандаш (редактирование подкатегории), «+» (добавление товара).
- **BR-NOM-038** — Категория с подкатегориями только раскрывается в дереве — список товаров по ней не открывается.
- **BR-NOM-039** — Подкатегория с группами по клику раскрывает свои группы. Подкатегория без групп открывает пустой список с текстом «Товаров пока нет. В этой подкатегории ещё не создано ни одного товара.» Добавить товар можно через «+».
- **BR-NOM-040** — Клик по фото товара открывает его в увеличенном виде; если фото нет — клик ничего не делает.
- **BR-NOM-041** — Название товара и его иконки формируются по блоку «По умолчанию» вкладки «Вывод данных»; список товаров сортируется по этому названию.
- **BR-NOM-042** — Вес в таблице показывается с надбавкой +5% к исходному.
- **BR-NOM-043** — Код и RC (региональный код, например X/A, ZD/A) редактируются кликом прямо в таблице, сохранение по Enter или клику вне поля. RC необязателен и назначается после создания товара — индивидуально или массово через «+ RC» сразу всем товарам списка.
- **BR-NOM-044** — Пара «код + RC» уникальна во всей номенклатуре (пример из ТЗ: MJXN4, MJXN4 X/A и MJXN4 ZD/A — три разных товара).
- **BR-NOM-045** — Массовое назначение RC применяется ко всем товарам списка, кроме тех, у кого пара «код + RC» уже существует; конфликты показываются списком.
- **BR-NOM-046** — Все товары выводятся сразу, без пагинации.
- **BR-NOM-047** — Действия в строке товара: редактирование, настройка сканирования, дублирование, удаление.

### Добавление товара

- **BR-NOM-048** — «+» над таблицей → окно «Добавить товар». После сохранения товары появляются в списке.
- **BR-NOM-049** — Фото необязательно; один файл любого формата изображения (PNG, JPG и т.д.); при загрузке конвертируется в WEBP.
- **BR-NOM-050** — Над полями формы выводится название товара по первой комбинации выбранных значений характеристик; обновляется по мере заполнения формы.
- **BR-NOM-051** — Код обязателен (буквы и цифры), уникален в паре с RC, генерируется автоматически. Если создаётся ровно один товар — код можно ввести вручную; если после ручного ввода выбрано несколько значений характеристик — код сбрасывается обратно на автоматический.
- **BR-NOM-052** — Вес обязателен, положительное число в граммах. Хранятся оба значения — исходный вес и вес с надбавкой +5% (итог показывается рядом с полем).
- **BR-NOM-053** — Поля характеристик берутся из вкладки «Главные», отображаются по алфавиту, все обязательны; в каждой характеристике можно выбрать одно или несколько значений.
- **BR-NOM-054** — Если в одной или нескольких характеристиках выбрано несколько значений — создаётся отдельный товар на каждую комбинацию.
- **BR-NOM-055** — Если хотя бы одна из создаваемых комбинаций уже существует в группе — сохранение запрещено; показывается, какие комбинации уже существуют.
- **BR-NOM-056** — Кнопка «Save» активна только когда заполнены все обязательные поля.

### Настройка сканирования

- **BR-NOM-057** — Иконка сканирования в строке товара → окно «Настройка сканирования»; настройка задаётся индивидуально для этого товара.
- **BR-NOM-058** — Три режима: «Без IMEI» (по умолчанию, товар не сканируется), «Один», «Два» (количество IMEI у устройства; обычно два — у устройств с двумя SIM). Поля формы одинаковые в режимах «Один» и «Два».
- **BR-NOM-059 (Код производства)** — Обязателен в режимах «Один»/«Два»; только цифры; глобально уникален (один код нельзя указать у двух разных товаров). Тумблер «Больше одного» позволяет добавить несколько кодов списком; каждый код удаляется отдельно (иконка корзины).
- **BR-NOM-060 (Количество символов)** — Обязательно в режимах «Один»/«Два»; задаёт допустимую длину серийного номера для проверки товара; можно указать одно или несколько значений через запятую (пример из ТЗ: «11, 15» → подходит номер из 11 или 15 символов, 14 символов — не подходит).

### Редактирование товара

- **BR-NOM-061** — Карандаш в строке товара → окно с текущими данными товара. Поля те же, что при добавлении (фото, код, вес, характеристики), но в каждой характеристике выбирается только одно значение (не несколько).
- **BR-NOM-062** — Код можно изменить; действуют те же правила, что при добавлении (BR-NOM-051, BR-NOM-044).
- **BR-NOM-063** — В поле веса показывается исходный вес с весов и итог с надбавкой +5% рядом; хранятся оба значения.
- **BR-NOM-064** — Если новая комбинация характеристик уже существует в группе — сохранение запрещено.
- **BR-NOM-065** — Если товар в продаже и меняются характеристики — показывается предупреждение: «Товар в продаже. Изменение поменяет его название. Продолжить?»
- **BR-NOM-066** — Загруженное фото показывается превью; можно заменить или удалить.

### Дублирование товара

- **BR-NOM-067** — Иконка дублирования в строке товара → окно добавления, предзаполненное данными исходного товара. «Save» создаёт новые независимые товары.
- **BR-NOM-068** — Все поля, включая фото, скопированы из исходного товара и доступны для изменения; действуют те же правила, что при добавлении — можно выбрать несколько значений и создать сразу несколько товаров.
- **BR-NOM-069** — Код новый, генерируется автоматически; если создаётся один товар — можно ввести вручную.
- **BR-NOM-070** — Если хотя бы одна комбинация уже существует в группе — сохранение запрещено.
- **BR-NOM-071 (НЕ ПОДТВЕРЖДЕНО)** — Раздел ТЗ «Что переносится в новый товар» (стр. 7 исходного документа) пуст — содержимое не специфицировано автором ТЗ. Требует уточнения у QA Lead перед детальным тестированием этапа «Копирование». См. `open-questions.md` Q-002.

### Удаление товара

- **BR-NOM-072** — Корзина в строке товара → мягкое удаление с подтверждением «Удалить товар «Название»?»
- **BR-NOM-073** — Нельзя удалить товар, если он есть в стоке у поставщика; показывается, у какого именно поставщика.
- **BR-NOM-074** — Вместе с товаром удаляются его настройки: проценты, карго, гарантии, привилегии поставщика.
- **BR-NOM-075** — Оформленные заказы не затрагиваются; купить удалённый товар заново нельзя.
- **BR-NOM-076** — Требуется право «удаление».

### Архив

- **BR-NOM-077** — Вкладка «Архив» расположена рядом с «Номенклатурой»; содержит удалённые элементы и товары, которые год не продавались. Слева дерево, справа — товары выбранной группы.
- **BR-NOM-078** — В архив попадает удалённый бренд/категория/подкатегория/группа/товар вместе со всем вложенным и привязанными настройками (проценты, карго, гарантии, привилегии поставщика).
- **BR-NOM-079** — Товар автоматически уходит в архив, если 365 дней по нему нет заказов ни в одной связке, и у поставщиков нет стока по нему.
- **BR-NOM-080** — Поставщик не может выставить архивный товар на продажу.
- **BR-NOM-081** — В дереве архива видны родители архивного элемента — для возможности его найти.
- **BR-NOM-082** — Restore доступен: правый клик по папке; кнопка в строке товара; кнопка над таблицей (восстановить все товары группы разом).
- **BR-NOM-083** — Восстановление товара → автоматически восстанавливаются его удалённые родители. Восстановление папки → восстанавливается всё вложенное.
- **BR-NOM-084** — После восстановления всё возвращается как было, включая состояние тумблера продажи на странице «Проценты».
- **BR-NOM-085** — Нельзя восстановить, если такая же комбинация характеристик или пара «код + RC» уже существует; показывается, что именно мешает восстановлению.
- **BR-NOM-086 (НЕ ПОДТВЕРЖДЕНО)** — Восстановить можно в течение 30 дней; в самом ТЗ этот порог помечен автором как «уточняется». После истечения срока элемент пропадает из архива. См. `open-questions.md` Q-003.
- **BR-NOM-087** — Причина и дата попадания в архив записываются в логи (Management → Logs — предположительно, не подтверждено явной ссылкой в ТЗ).
- **BR-NOM-088** — Требуется право «удаление».

## 4. Пользовательские сценарии

1. **Построение иерархии:** создать бренд → создать категорию внутри бренда → создать подкатегорию внутри категории → задать характеристики и вывод данных подкатегории → добавить товары в подкатегорию (группу).
2. **Изменение существующей структуры:** переименовать/отредактировать бренд, категорию или подкатегорию через контекстное меню; изменить порядок элементов перетаскиванием.
3. **Удаление с каскадом:** удалить категорию → проверить, что вложенные подкатегории, их товары и привязанные настройки (проценты/карго/гарантии/привилегии поставщика) тоже помечены удалёнными (мягко) и доступны в Архиве.
4. **Работа с товаром:** добавить товар с несколькими значениями характеристик (мультисоздание) → отредактировать один товар (сузить до одного значения в характеристике) → настроить сканирование (IMEI) → продублировать товар → удалить товар.
5. **Восстановление из архива:** найти удалённый элемент в Архиве (через родителей) → восстановить → убедиться, что восстановилось всё вложенное и настройки (включая тумблер продажи в «Процентах»).
6. **Наследование характеристик:** создать подкатегорию без собственных характеристик (наследует от категории) → добавить свою характеристику → убедиться, что наследование от родителя прекратилось.

## 5. Состояния страницы

- **Loading:** не специфицировано явно в ТЗ — поведение при загрузке дерева/таблицы товаров уточняется при осмотре UI.
- **Loaded:** дерево номенклатуры и (при выбранной группе) таблица товаров отображены.
- **Empty:** подкатегория без групп товаров → «Товаров пока нет. В этой подкатегории ещё не создано ни одного товара.» (BR-NOM-039).
- **Error:** валидационные сообщения — см. раздел «Ошибки» (BR-NOM-014…BR-NOM-017); конфликты кода+RC и комбинаций характеристик (BR-NOM-044, BR-NOM-055, BR-NOM-064).
- **Success:** явные success-тосты в ТЗ не описаны — визуальное обновление дерева/таблицы после сохранения. Уточняется при осмотре UI.
- **Disabled:** кнопка «Save» неактивна, пока не заполнены обязательные поля (BR-NOM-056); вкладка «Вывод данных» неактивна, если у категории/подкатегории ещё нет своих характеристик (BR-NOM-034).

## 6. Связи и зависимости

- **Settings → Users** — права доступа (просмотр/редактирование/удаление) к Номенклатуре (BR-NOM-018).
- **Settings → Characteristics** — «Справочник» характеристик, из которого выбираются характеристики для категорий/подкатегорий (BR-NOM-023).
- **Settings → Percents, Cargo, Warranty, Compensation** — настройки, привязанные к бренду/категории/подкатегории/товару; удаляются и восстанавливаются каскадно вместе с Номенклатурой (BR-NOM-012, BR-NOM-074, BR-NOM-078, BR-NOM-084).
- **Management → Logs** — предположительно, лог причины/даты попадания в архив (BR-NOM-087, не подтверждено).
- **Suppliers / поставщики (привилегии поставщика)** — настройки привилегий поставщика привязаны к бренду/категории/товару, удаляются/восстанавливаются каскадно.
- **Видимость и таргетинг товара для поставщика и клиента** — по словам QA Lead, настройки бренда/категории/модели влияют на то, как товар виден поставщику и клиенту и как он таргетируется. Механизм не описан в изученном ТЗ — требует отдельного уточнения (см. `open-questions.md` Q-004).
- **Регрессионные риски:** изменение «Вывод данных» переименовывает уже существующие товары (BR-NOM-033) — риск для любых сохранённых ссылок/отчётов по старому названию; удаление бренда/категории каскадно затрагивает Проценты/Карго/Гарантии/привилегии поставщика — риск для уже сконфигурированных настроек этих разделов.
